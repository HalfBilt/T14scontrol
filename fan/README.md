# ThinkPad T14s Gen 4 智能风扇控制（服务版）

针对 **ThinkPad T14s Gen 4（ES 工程机 + 工程 BIOS）** 的智能风扇控制。

**2026-10-20 重大变更**：托盘程序已删除，改成 **Windows 服务（SYSTEM 常驻）**；
驱动从 PawnIO 换成 **TSCtl**（与 CPU 侧功耗墙工具同一个驱动）。

## 为什么这么改

| 问题 | 原因 | 现在的做法 |
|---|---|---|
| 托盘只在**登录后**运行 | 不登录就没有风扇控制，只剩固件原生曲线（实测天花板 ≈3890 RPM，压不住满载） | 做成服务，SYSTEM 开机常驻，不依赖登录 |
| PawnIO **拒绝 SYSTEM 账户** | `pawnio_open` 返回 `0x80070005`，服务模式根本打不开驱动 | 改用 TSCtl（CPU 侧一直在用，SYSTEM 完全可用） |
| 两个进程抢 EC 端口 | 之前两边用**不同的互斥锁** → 互相插队 → 抢走系统 ACPI EC 驱动正在等的字节 → ACPI 事件 13 → DSDT 的 `_TMP` 拿不到温度 → 固件报 `_HOT` → **凉机强制休眠**（2026-10-20 11:47 / 12:31 实录，当时 EC 只有 58°C） | 风扇侧直接 **import CPU 侧的 `CpuPLFix.py`**，复用它的 EC/MSR 访问层和 `Global\CpuPLFix-EC` 锁 → 两进程真正串行化 |
| 固件每 ~30 秒重写 `0x2F` | 联想 BIOS 的原生风扇曲线在按自己的阈值改写 HFSP；温度 60~63°C 时它选 `0x01`(2471 RPM) —— **这就是"风扇几乎不转"的真凶** | 服务常驻 + **档位守望**：每个 EC 周期核对一次，固件给的档位**比我们要的弱**就立刻重写（更强就接受，不跟它拉锯） |

## 安装 / 日常

```
1-安装风扇服务.bat     注册并启动 T14sFanSvc(需要管理员)
2-卸载风扇服务.bat     停止并删除
3-风扇服务状态.bat     看状态 + 最近日志
4-重启风扇服务.bat     重启
```

- 日志：`fan_service.log`（服务）/ `fan_control.log`（前台调试模式）
- 配置：`config.json`（改完 60 秒内生效，或重启服务）
- 离线自测：`..\runtime\python.exe src\fan_control.py --selftest`

## 模式

**只有一种：智能模式。** 托盘已删，`config.json` 里的 `mode` 会被服务强制为 `smart`
（旧的 `auto` 会让档位完全交给固件 —— 固件在 60°C 只给最低档）。

## 曲线（按**实测转速**排，不是按档位号）

本机全档位实测（手册 `scripts/风扇档位-20261020-075530.txt`，逐档等 25 秒取中位）：

| 档 | 0x01 | 0x02 | 0x03 | 0x04 | 0x05 | 0x06 | 0x07 | 0x40 |
|---|---|---|---|---|---|---|---|---|
| RPM | 2471 | 2858 | 3181 | 3186 | 3167 | **3456** | 3858 | 4807 |

`0x03/0x04/0x05` 三档挤在 ~3180 RPM，物理上几乎没有区别 → 当不了中间档，直接跳过。
`0x40` 是唯一确定的满速，但**要 20~25 秒才爬到位**。

> ⚠️ 表里是**低温标定值**：`0x06` 热态会到 ~3880、`0x07` 热态到 ~4380（EC 内部像带历史/
> 回差的状态，不是按当前温度瞬时切换）。曲线只按档位顺序决策，不看 RPM 数字。
> 重新标定每档至少等 **45 秒**——14~25 秒会把没爬完的转速当成稳态（`0x08` 的假象就是这么来的）。

| 温度 | 档位 | RPM |
|---|---|---|
| ≤50°C | 0x01 | 2471 |
| 50~62°C | 0x02 | 2858 |
| 62~72°C | 0x06 | 3456（热态 ~3880） |
| 72~80°C | 0x07 | 3858（热态 ~4380） |
| ≥80°C | 0x40 | 4807（满速） |

> ⚠️ **别抄旧表**：更早的 README 里那张（2029/2362/2600/2964/3185/3170/3924/4946）是从别的
> 机型搬来的，本机实测对不上。现在这张是本机实测值。

> **不写 0x31**：老 IBM/X60 那代才用它选主/副风扇；本机 0x31 是 HUWB/VPON/VRST，
> 写 0 会清掉 VPON/VRST 位，而实测写与不写转速完全一样。

## 其余机制

- **曲线输入 = `max(EC 0x78, DTS-6)`**：稳态按 EC 走（不会一直偏吵），冲载时 DTS 提前 5~8 秒顶档
- **DTS 快速通道**：MSR `0x1B1` 算封装温度，**≥88°C 连续两拍且 PKG≥25W** 才锁存拉满，
  降到 ≤84°C 解除（比 EC 快 6~13°C）
- **功耗前馈**：RAPL `MSR 0x611/0x606`，**≥50W 持续 4 秒**抬到 7 档
- **负载前馈**：系统占用 **≥70% 持续 5 秒**抬到 7 档；回落到 55% 以下持续 10 秒才解除
- **前馈只抬不压**：前馈只会把档位往上抬，不会把曲线算出的更高档位压下来
- **失效保护**：EC ≥88°C 无条件拉满速，降温后自动恢复
- **EC 温度哨兵**：`0x78` 只接受 0~127，越界值（实测偶发 132）直接丢弃
- **不抢别人的 EC 字节**：事务开始前先看状态口，OBF 挂着就跳过这一轮（那字节多半是系统
  ACPI EC 驱动 `_TMP` 正在等的；抢走 = 对方超时 = 固件报 `_HOT` = 强制休眠）
- **满速退出温度单独画**（`max_exit_c=74`）：进满速 80°C、退 74°C。满速光爬速就要 20~25 秒，
  退回 7 档等于白爬
- **满速功耗门**（`full_exit_pkg_w=25`）：封装功耗仍 ≥25W 时不退满速 —— 28W 满载下
  7 档压不住（实测爬到 95°C），EC/DTS 短暂掉到 74°C 以下也不该退
- **降档驻留 90 秒（满速档 45 秒）**、回差 6°C：防止在边界上反复换挡；满速档
  与热态 7 档（~4380 RPM）只差 ~420 RPM，负载结束后更早回落
- **唤醒自愈**：SCM 的电源事件（睡眠/休眠恢复/拔插电）到达后 1 秒内重读温度并重写档位
  （固件 `OWAK()` 会在唤醒时抢档）
- **接管即摆正**：服务启动/唤醒后**立刻**按曲线写一次档位（固件可能已经按到 0x01）
- **日志自动轮转**：3MB 上限，正常时仅换档才写日志

## 背景：这台机器的风扇天花板

该工程机 BIOS 按 CPUID 匹配风扇曲线失败，回退到一张很平的 EC 曲线 —— 实测
**原生自动（0x80）最高只到 ≈3890 RPM**，无论 54°C 还是 99°C 几乎不变，压得住轻载、
压不住满载（28W 满载会稳定在 95~99°C）。本工具绕过固件，直接读写 EC 寄存器
（HFSP=`0x2F`，`0x80`=EC自动 / `0x40`=满速，档位 `0x00~0x07`）。

## 不要做的事

- 不要和 TPFanCtrl2 / ThrottleStop / HWiNFO 的 EC 访问同时跑
- 不要 `powercfg /h off` 关休眠：`_HOT` 触发时就只剩"紧急关机"一条路，会丢数据
- 不要在满载时批量扫描 EC（本机 EC 是慢总线，串位率 8~27%）

## 与 CPU 侧工具的关系

`%APPDATA%\T14scontrol\cpu\` 里的 CpuPLFix 负责**功耗墙（MSR/MMIO）+ 过热保护**，
只读 EC 温度/标志、**不写 EC**；本工具负责**风扇（写 EC 0x2F）**。两边互不写对方的寄存器，
但共用 EC 总线 —— 所以共用同一把 `Global\CpuPLFix-EC` 锁，顺序一致，不会插队。
