T14s 智能风扇控制 —— 使用说明（服务版）
========================================
2026-10-20 改版：托盘程序已删除，改成 Windows 服务（SYSTEM 常驻）。

【为什么改】
  1. 托盘只在登录后运行 —— 不登录就没有风扇控制（只剩固件原生曲线，
     实测天花板 ≈3890 RPM，压不住满载）。
  2. PawnIO 驱动拒绝 SYSTEM 账户 -> 服务模式打不开驱动，已改用 TSCtl
     （与 CPU 侧功耗墙工具同一个驱动）。
  3. 固件每 ~30 秒重写 0x2F（联想 BIOS 原生曲线），温度 60~63°C 时它选
     0x01(2471 RPM) —— 这就是"风扇几乎不转"的真凶。服务常驻后会盯住。

【怎么用】
  1-安装风扇服务.bat    注册并启动（需要管理员）
  3-风扇服务状态.bat    看状态 + 最近日志
  4-重启风扇服务.bat    重启
  2-卸载风扇服务.bat    停掉并删除

  日志：fan_service.log      配置：config.json
  离线自测：runtime\python.exe src\fan_control.py --selftest

【模式】
  只有智能模式一种。托盘已删，config.json 里的 mode 会被服务强制成 smart。
  （旧的 auto 会把档位完全交给固件 —— 固件在 60°C 只给最低档。）

【曲线（按实测转速排）】
  ≤50°C->1档(2471)  50~62->2档(2858)  62~72->6档(3456)
  72~80->7档(3858)   ≥84->满速(4807)
  0x03/0x04/0x05 三档实测都挤在 ~3180 RPM，没有中间档的意义，直接跳过。

【参数（config.json）】
  cycle_sec=5        EC 温度轮询间隔(秒)
  tick_sec=2         决策间隔(秒, 走 MSR+API 不碰 EC)
  hysteresis=4       降档回差(°C)
  dts_max_c=88       DTS 到 88°C 立刻拉满
  dwell_s=60         换档后 60 秒内不降档
  max_exit_c=74      满速档退到 74°C 才退
  curve              上面那张曲线

【与 CPU 侧的关系】
  ..\cpu\ 里的 CpuPLFix 管功耗墙(MSR/MMIO)+过热保护，只读 EC 不写 EC；
  本工具管风扇(写 EC 0x2F)。两边共用同一把 'Global\CpuPLFix-EC' 锁，
  顺序一致 -> 不会互相插队 -> 不会再出现"凉机强制休眠"(Event 88)。

【别做的事】
  - 不要和 TPFanCtrl2 / ThrottleStop / HWiNFO 的 EC 访问同时跑
  - 不要 powercfg /h off 关休眠
  - 不要在满载时批量扫描 EC
